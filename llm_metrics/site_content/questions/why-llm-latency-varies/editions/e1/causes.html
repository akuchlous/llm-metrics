• Load and queueing: requests from many customers share the same hardware. When demand is high, a request may wait before the model starts on it, which mainly raises time to first token.
  • Batching: providers process several requests together for efficiency. Which batch a request joins, and how busy that batch is, affects both waiting and generation speed.
  • Network path: the connection setup, the distance to the serving region and the route across the internet add a variable delay on both ends.
  • Prompt caching: some providers reuse work for prompts they have seen recently. A cache hit can start the answer sooner than a cache miss for the same prompt.
  • Answer length: unless the output is fixed, the same prompt can produce longer or shorter answers, and longer answers take longer to generate.
  • Retries and errors: client libraries may retry failed requests automatically, which hides a failure inside one long request. Our benchmark disables such retries so each request is measured once.
