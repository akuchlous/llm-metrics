Retries are a common source of duplicate charges, so the paid path has none:

  • Cloud Scheduler is configured with zero retries. A missed delivery is a missed slot, never made up later.
  • Each provider request is exactly one HTTP request. We call the API directly instead of through the provider's SDK, partly because the SDK retries by default.
  • Saving the measurement record retries only the storage write, a bounded number of times, and never repeats the provider request. By the time a record exists, the measurement is over.
  • A slot stays consumed after a crash, a provider failure or a failed write. A later run for that slot finds the claim and skips.
