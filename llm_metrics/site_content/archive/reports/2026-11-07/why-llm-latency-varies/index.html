Question

Why can two requests to the same LLM have different latency?

Archived edition, published 7 November 2026 (UTC). Read the current answer.

Answer

LLM latency varies because a hosted model runs on shared, busy infrastructure. Two identical requests can wait in different queues, run on different servers, take different network paths, hit or miss a cache, and produce answers of different lengths. Each of these changes how long the request takes, so latency is best described as a distribution rather than a single number.

Common causes

  • Load and queueing: requests from many customers share the same hardware. When demand is high, a request may wait before the model starts on it, which mainly raises time to first token.
  • Batching: providers process several requests together for efficiency. Which batch a request joins, and how busy that batch is, affects both waiting and generation speed.
  • Network path: the connection setup, the distance to the serving region and the route across the internet add a variable delay on both ends.
  • Prompt caching: some providers reuse work for prompts they have seen recently. A cache hit can start the answer sooner than a cache miss for the same prompt.
  • Answer length: unless the output is fixed, the same prompt can produce longer or shorter answers, and longer answers take longer to generate.
  • Retries and errors: client libraries may retry failed requests automatically, which hides a failure inside one long request. Our benchmark disables such retries so each request is measured once.

How to measure it fairly

Because single requests vary, a fair measurement repeats the same request many times over a period that covers busy and quiet hours. It then reports percentiles: the median shows a typical request, and a high percentile such as p95 shows how slow the slow requests are. Failed requests should be counted separately, never as fast results.

The sample size and time window should always be shown with the numbers. A percentile from a handful of requests, or from a single hour, can be misleading.

Limitations

Measurements from one place describe that place. Latency seen from another region, network or account, or with a different prompt and settings, can differ. Providers also change their infrastructure over time, so older measurements may no longer apply.
