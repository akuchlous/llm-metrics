## Issues fixed

### 1 — Fail-fast on installation command failure

**Before:** `_install_docker_apt()` and `_install_docker_dnf()` ran `sudo
apt-get install` etc.  as plain statements.  If any command failed the
function continued, and the caller could print "installed" despite the
failure.

**After:** Each phase is wrapped in a subshell with `set -e`:

```bash
(set -e
    sudo apt-get update -qq
    sudo apt-get install -y ca-certificates curl
) || { fail "Step 1/4 failed: could not install prerequisites."; return 1; }
```

The interactive mode calls every install function with `|| exit 1`, so
there is no path that continues after a partial failure.

### 2 — DNF repo URL per distribution

**Before:** `_install_docker_dnf()` hardcoded the Fedora repo URL for all
dnf-based distros.

**After:** New `_dnf_docker_repo_url()` function:
- Fedora → `https://download.docker.com/linux/fedora/docker-ce.repo`
- RHEL / CentOS / Rocky / AlmaLinux → `https://download.docker.com/linux/rhel/docker-ce.repo`

### 3 — Docker group: root-equivalent warning + typed confirmation

**Before:** `_add_user_to_docker_group()` asked `[y/N]` with no security
explanation.

**After:** Prints a multi-line warning:

```
SECURITY: The 'docker' group grants root-equivalent access.
Group members can run containers that mount the host filesystem or
bypass container isolation, with the same effect as unrestricted sudo.
Only add users who already have unrestricted sudo access on this host.
```

Then calls `ask_yes()` which requires typing the word `yes`
(not just `y`) before `sudo usermod -aG docker $USER` is run.

### 4 — Compose-only install when Docker present but Compose v2 missing

**Before:** The script detected and reported missing Compose but offered
no fix.

**After:** When `$DOCKER_BIN` is set but `$COMPOSE_OK` is 0, interactive
mode offers `docker-compose-plugin` install via apt or dnf without
reinstalling Docker Engine:

```bash
if [ -n "$DOCKER_BIN" ] && [[ $COMPOSE_OK -eq 0 ]]; then
    # offer _install_compose_plugin_apt or _install_compose_plugin_dnf
fi
```

### 5 — VERSION_CODENAME validation for apt

**Before:** `_install_docker_apt()` used `VERSION_CODENAME` without checking
whether Docker publishes packages for it.

**After:** `_APT_KNOWN_CODENAMES` lists Ubuntu (focal / jammy / mantic /
noble / oracular) and Debian (bullseye / bookworm / trixie).
`_apt_check_codename()` warns on an unknown codename, lists the known
releases, and asks whether to continue.  An empty codename is an
immediate failure with a pointer to the manual install URL.

### 6 — Script sourceable for testing

**Before:** `main` ran unconditionally at the bottom of the file, so
sourcing the script from a test triggered the full interactive flow.

**After:**

```bash
if [[ "${BASH_SOURCE[0]}" == "${0}" ]]; then
    main
fi
```

Tests can now `source setup.sh` to call helper functions (e.g.
`_dnf_docker_repo_url`) directly.
