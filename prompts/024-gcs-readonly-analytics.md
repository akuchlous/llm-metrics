## Implement
- A small reusable Python module/CLI to load **only** canonical `llm-metrics.attempt.v1` real prod JSON files from a selected local directory; validate via existing object_results decode/record validation, do not duplicate schema or fetch from SQL. CLI requires explicit input and output paths; never reaches GCP/OpenAI automatically. Keep errors clear, inputs bounded, output deterministic and repeatable.
- Filter explicitly by exact provider/model/profile, workload, origin region and UTC start/end; don't mix old one-off pilot populations with scheduled pilot silently. Require a deliberate explicit filter to include the separate 018f/020 CSV backups (out of scope to import them now). Preserve origin and any absent provenance as absent, never invented.
- Compute a versioned machine-readable analytics summary: sample counts attempted/success/failed, observed success rate; valid-success-only TTFT and total-latency p50/p95 and latest/min/max as justified; throughput stats; sum known API costs, failed-cost-unknown count, tokens; earliest/latest UTC data; exact filter/profile/workload; evidence records count and individual identifiers/checksums or reproducible manifest. Keep failures in reliability denominators and never manufacture 0 latencies. Do **not** claim every scheduled slot succeeded from records alone; show slot completeness only if independently supplied verified claim/audit evidence. Explain partial-day/small-n caveats and p95 limitations.
- Write stable schema `llm-metrics.analytics.v1` in canonical JSON using atomic local filesystem write (temp + rename), no secrets or prompt/response text. Make repeated runs byte-for-byte identical for identical inputs (use explicit as-of timestamp or omit wall-clock-generated fields). Check collisions, malformed JSON, invalid schema, duplicates, mixed populations, null/nonfinite metric handling, corrupted attempts, zero rows, and path traversal/symlink concerns.
- Tests with realistic committed synthetic **prod-labeled but clearly synthetic** fixtures only, plus error/missing boundary cases. Never commit genuine provider request IDs or confidential data. README/CLI usage with exact sample command. No new DB, Redis, hosted job or framework.

## Acceptance

A missing or invalid input must not publish plausible-looking results. No Cloud access is needed. Future static pages can consume only the summary schema, not reread provider APIs.
