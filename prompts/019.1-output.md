## setup.sh behaviour

**Check mode (`./setup.sh --check`):**
- Detects OS and package manager (Debian/Ubuntu → apt; RHEL/Fedora/CentOS/Rocky/Alma → dnf; macOS → brew)
- Checks docker binary, `docker compose version`, and daemon access (`docker info`)
- Reports each component's status
- Describes what install would do (without doing it)
- Exits 0 if all three checks pass, non-zero otherwise
- Makes no system changes

**Interactive mode (`./setup.sh`):**
- Same detection and reporting as check mode
- For each missing component, shows the exact commands that will run and asks for Y/N confirmation
- Docker Engine install (Ubuntu/Debian): adds Docker's official apt repository, downloads GPG key to a file (NOT curl-pipe-shell), installs `docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`
- Docker Engine install (RHEL/Fedora/dnf): adds Docker's official dnf repository, installs same packages
- Docker Engine install (macOS + Homebrew): `brew install --cask docker`
- Daemon not running: offers `sudo systemctl enable --now docker`
- Socket permission error: offers `sudo usermod -aG docker $USER`, explains logout/newgrp
- Never installs PostgreSQL, Python, pip, or any application service
- Never uses Google Cloud

**`./setup.sh --help`:** Prints the script header as usage text.

**Idempotent:** Safe to re-run when Docker is already installed (reports "ready", exits 0).

## Platform limitations

| Platform | Auto-install | Notes |
|---|---|---|
| Ubuntu / Debian | Yes | Official Docker apt repository; `VERSION_CODENAME` required in `/etc/os-release` |
| RHEL / Fedora / CentOS / Rocky / AlmaLinux | Yes | Official Docker dnf repository |
| macOS (with Homebrew) | Yes | `brew install --cask docker` (Docker Desktop); must start Docker Desktop manually after install |
| macOS (without Homebrew) | No | Displays download URL; prompts to install Homebrew first |
| WSL2 | No | Docker Desktop for Windows handles daemon; setup.sh explains the WSL integration steps |
| Other Linux | No | Displays official Docker install URL |

## Security properties

- No curl-pipe-shell (`curl ... | bash/sh`) installers. The apt-based install downloads `https://download.docker.com/linux/debian/gpg` to a file with `curl -fsSL ... -o /etc/apt/keyrings/docker.asc`. This is a binary GPG key (not a script), consistent with Docker's official documentation.
- Every `sudo` call is for a specific, described operation: `apt-get`, `dnf`, `install`, `curl`, `usermod`, `systemctl`. The user sees the commands before confirming.
- No silent system changes. `CHECK_ONLY=1` returns without touching any state.
