## setup.sh behaviour

**Check mode (`./setup.sh --check`):**
- Detects OS and package manager (Debian/Ubuntu → apt; RHEL/Fedora/CentOS/Rocky/Alma → dnf; macOS → brew)
- Checks docker binary, `docker compose version`, and daemon access (`docker info`)
- Reports each component's status (all three checked even if first fails)
- Describes what install would do (without doing it)
- Exits 0 if all three checks pass, non-zero otherwise
- Makes no system changes

**Interactive mode (`./setup.sh`):**
- Same detection and reporting as check mode
- For each missing component, shows the exact commands that will run and asks for Y/N confirmation
- Docker Engine install (Ubuntu/Debian): adds Docker's official apt repository, downloads GPG key to a file (NOT curl-pipe-shell), installs `docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`
- Docker Engine install (RHEL/Fedora/dnf): adds Docker's official dnf repository (Fedora-specific URL for Fedora; RHEL URL for RHEL/CentOS/Rocky/Alma), installs same packages
- **Docker Compose plugin only** (new): when Docker is installed but Compose v2 missing, offers to install only `docker-compose-plugin` via apt or dnf
- Docker Engine install (macOS + Homebrew): `brew install --cask docker`
- Daemon not running: offers `sudo systemctl enable --now docker`
- Socket permission error: warns of **root-equivalent access** (explicit security warning), requires typing 'yes' (not just 'y'), then offers `sudo usermod -aG docker $USER`
- Never installs PostgreSQL, Python, pip, or any application service
- Never uses Google Cloud

**`./setup.sh --help`:** Prints the script header as usage text.

**Idempotent:** Safe to re-run when Docker is already installed (reports "ready", exits 0).

## Fixes applied in 019.1 review

1. **Fail-fast on install failure:** `_install_docker_apt`, `_install_docker_dnf`, `_install_compose_plugin_apt`, `_install_compose_plugin_dnf` now wrap each phase in a subshell with `set -e`.  Any command failure exits the subshell; the outer function returns 1 and prints which step failed.  The interactive mode calls `|| exit 1` after each install function — no partial-success path exists.

2. **DNF repo URL per distribution:** New `_dnf_docker_repo_url()` function: Fedora → `https://download.docker.com/linux/fedora/docker-ce.repo`; RHEL/CentOS/Rocky/Alma → `https://download.docker.com/linux/rhel/docker-ce.repo`.

3. **Docker group: root-equivalent warning + typed confirmation:** `_add_user_to_docker_group()` now prints an explicit multi-line security warning ("Group members can run containers that mount the host filesystem..."), then calls `ask_yes` which requires the user to type the word `yes` (not just `y`).

4. **Compose-only install path:** When `$DOCKER_BIN` is set but `$COMPOSE_OK` is 0, interactive mode offers to install only the Compose plugin (`_install_compose_plugin_apt` / `_install_compose_plugin_dnf`), without reinstalling Docker Engine.

5. **Known-codename validation for apt:** `_APT_KNOWN_CODENAMES` lists Ubuntu (focal/jammy/mantic/noble/oracular) and Debian (bullseye/bookworm/trixie) releases.  `_apt_check_codename()` warns and offers to abort if `VERSION_CODENAME` is not in the list.  Empty codename is an immediate failure with a pointer to the manual install URL.

6. **Test count documentation:** 6 tests are in `SetupScriptTest`, 1 (`test_no_docker_mentions_setup_sh`) is in `RunScriptTest`.  PROJECT_STATUS.md now reads "6 in SetupScriptTest + 1 in RunScriptTest (total 7)".

## Security properties

- No curl-pipe-shell (`curl ... | bash/sh`) installers. The apt-based install downloads `https://download.docker.com/linux/{ubuntu|debian}/gpg` to a file with `curl -fsSL ... -o /etc/apt/keyrings/docker.asc`. This is a binary GPG key (not a script), consistent with Docker's official documentation.
- Every `sudo` call is for a specific, described operation: `apt-get`, `dnf`, `install`, `curl`, `usermod`, `systemctl`. The user sees the commands before confirming.
- Docker group add explicitly warns that group membership = root-equivalent access and requires typing 'yes'.
- Fail-fast: no sudo operation continues after a previous step fails.
- No silent system changes. `CHECK_ONLY=1` returns without touching any state.
