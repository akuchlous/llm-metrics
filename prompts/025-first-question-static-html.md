# Step 025 — First question-driven static HTML analytics page, local only

**One micro-step.** Make one genuinely useful, accessible static HTML page from a Step 024 validated analytics JSON artifact. No hosting, cloud deployment, scheduled regeneration, dated-version alias, provider calls, or collector modifications in this step.

## Product direction
The website is **question-first**, not dashboard-first. The first page asks: **“How do you measure OpenAI API time to first token (TTFT), and what does our interactive-chat benchmark show?”** Structure: question/title -> concise answer -> method -> key findings -> metrics/dashboard-style evidence. Do not title it a broad “fastest model” ranking: we currently measure only one OpenAI profile, one fixed workload, one origin, and partial-day samples.

## Implementation
- Read Step 024 report, code/schema and validation tests first; only use the defined summary, never simulated examples in a production page. Create a deterministic local static site generator with a small template and minimal CSS, reusing the current Jinja/template infrastructure if appropriate **without** coupling it to live Flask or SQL. Output an `index.html` under a configurable local directory and a CSS asset. Generating HTML needs no HTTP service or GCS access. Use safe HTML escaping for all data and an appropriate Content Security Policy if feasible for static hosting.
- Article should explain measured TTFT boundary (first actual streamed token rather than first byte), fixed versioned prompt scenario (fictional Lumen Notes offline synchronization), requested output cap 300, `gpt-6-luna`/`openai.gpt-6-luna.v1`, `interactive-chat-v1`, explicit no reasoning, cache policy disabled, from GCP us-central1. Reflect actual code definitions; explain that we do not store prompt or response, grade answer quality, or know cross-provider rankings. The methodology and context should remain accurate even if today's numbers change.
- Evidence cards/chart/table from REAL validated Step 024 summary: TTFT distribution p50/p95, total latency, throughput, count, failures, date range, origin, token/cost summary with unknowns. Use accessible semantic HTML and, if useful, a static SVG or simple CSS bars based on factual values (no heavy client JS or untested third-party CDNs). Units, missing-values and low sample sizes visible; “No validated data” state rather than fake values; methodology/version and dataset fingerprint visible.
- Preserve clear separation: human-authored explanatory text vs numeric values rendered from summary. An automatic refresh must never silently rewrite an editorial conclusion or title when stats change. Tests cover escaping/XSS, missing fields, failure/no-data state, deterministic HTML, links, filenames, mobile readability/accessibility basics. Add local preview directions using a file browser or local static server; no public domain or route changes.

## Acceptance
A developer can run offline fixture -> analytics JSON -> one readable static HTML page and inspect real-style charts without any hosted app, SQL, GCP or paid provider call. Report exactly which parts were based on synthetic test data vs actual verified data; **do not claim production launch**.
