## Phase 0 — offline code and read-only planning

Implement a **separately selected scheduled execution path**; leave existing one-off OpenAI/GCS and PostgreSQL/SQL fail-closed behavior unchanged. No arbitrary provider, model, workload, region or price changes. No provider retries, substitutions or fallback.

**Atomic slot gate:** define UTC quarter-hour slots (:00/:15/:30/:45). Before a paid provider call, create one immutable GCS claim using a server-side create-only precondition and verify it by reading back. Key it by exact profile/workload/origin and UTC slot; use one attempt UUID which is logged and later used by the GCS measurement. A duplicate or conflicting invocation must skip without provider call. Treat an ambiguous/failed claim as refusal, not permission to spend. A claimed slot stays consumed even if the job crashes or result saving fails; never automatically repeat the paid request. Validate the clock, reject late starts (propose a narrow 0–7 minute slot-start window), avoid caller-supplied timestamps that could create extra slots, and document limits of wall-clock scheduling. Demonstrate concurrency safety in offline tests.

**96-call ceiling:** an approved activation policy limits execution to precisely 96 consecutive quarter-hour slots, aligned to a UTC boundary. The policy has fixed start and expiry timestamps; reject missing, invalid, future or expired policy. Recheck expiry immediately before the paid call. No invoker-accessible switch may extend the window. Once expired, further scheduler deliveries must not call OpenAI even if the scheduler remains enabled. A durable claim permits at most one paid initiation per allowed slot, including manual duplicate starts. Explicitly acknowledge that this constrains only the guarded scheduled path, not unauthorized alternative deployments or total GCP charges. Design an access model that reduces bypass: preferably a dedicated scheduled Cloud Run Job and least-privilege invoker, with provider credentials available only to that guarded job. Leave the existing manual job credential-free if using a separate scheduled job.

**Monitoring:** log only sanitized metadata: scheduled slot, actual start, claim UUID, attempt initiated, duplicate skip, refusal, result persisted, provider failure, exit 3, job error and expiry. Separate expected slots, attempted calls, recorded results, successful responses, failed results and missing records. Build a simple read-only audit/reconciliation command for GCS claims, immutable prod records and available Cloud Run/Scheduler execution information. Detect missing slots, claim-without-record, exit 3 and duplicate trigger attempts. Configure actionable failure/missed-run alerts, verified with synthetic tests and no paid calls. The remaining crash window after a paid response but before GCS persistence is not solved by the claim; report it correctly. Do not log entire records, raw provider errors, prompts, completions or credentials.

**Probe cleanup:** investigate lifecycle policies carefully. Never apply bucket-wide deletion that can remove production observations, claims or prior backups. If a verified prefix-specific cleanup is not possible, keep tiny probes and report the negligible cost. Do not silently delete historical records.

**Cost and control:** aim for under $1/day for the pilot and the project's $10/day guideline. Verify official model pricing plus expected Cloud Run time, Scheduler, GCS operations, logging and monitoring. Billing budget alerts are **not** hard caps; the atomic slot gate and finite policy are the request controls. Include an emergency-stop procedure that disables Scheduler and removes provider access, noting that already-started executions can retain injected credentials.

**Offline tests:** failure before provider call on config/claim/clock/expiry/IAM errors; concurrent duplicate claims; exactly 96 allowed UTC slots even across midnight; out-of-window and late deliveries; no retry after crashes; missing-record audit; exit 3; sanitized logs; simulated provider error/nulls; SQL guard and ordinary manual run regressions.
